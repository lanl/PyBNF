# Lesson 18 — Fitting count data (the negative-binomial likelihood)

**Feature:** the `neg_bin` count noise model · **Difficulty:** ★★☆

Every fit so far scored a smooth curve with continuous scatter. Real single-molecule
data — smFISH spot counts, sequencing reads, colony counts — are **integers**, and
usually **over-dispersed**: their spread is wider than a Poisson's. Scoring them
with least squares quietly makes two wrong assumptions (symmetric, constant-width
noise; predictions that can go negative). This lesson fits counts with the noise
model built for them — the **negative binomial** — in one config line.

## The scenario

Transcription is shut off and a pool of `N0` mRNA molecules degrades first-order
(`mrna_decay.bngl`):

```
dA/dt = -k_deg * A        A(t) = N0 * exp(-k_deg * t)
```

At each time point we **count** molecules. The committed `mrna_decay.exp` is exactly
that: integer counts, drawn from a negative binomial whose mean is the model curve
`A(t)` and whose dispersion `r = 40` makes them over-dispersed (variance
`= mean + mean²/r`, so ~6× a Poisson at the early high-count points). There is **no
`_SD` column** — a count likelihood sets its own scale.

## The count likelihood, in one line

```
noise_model = neg_bin, dispersion = fix_at 40, location = mean
```

- **`neg_bin`** scores each count against the negative-binomial probability of
  observing it given the model's predicted mean `A(t)`. Non-negativity and the
  right-skew near zero come for free.
- **`location = mean`** says `A(t)` is the *mean* count — which is what the
  deterministic ODE computes. The negative binomial is right-skewed, so its mean and
  median differ; `neg_bin` defaults to `median`, so you say `mean` to match how the
  counts were generated. (Get this wrong and the fit is biased by the mean–median
  gap.)
- **`dispersion = fix_at 40`** pins the over-dispersion `r`. In practice you
  calibrate `r` from replicate measurements and hold it fixed, because estimating it
  *jointly* with the count scale `N0` is weakly identified — a larger `N0` with a
  wider assumed spread looks much the same. (To estimate it anyway:
  `dispersion = fit r_disp`, then declare `r_disp` a free parameter.)

The early points pin `N0`, the slope pins `k_deg`, and both come back from the noisy
counts:

```bash
pybnf -c mrna_decay_neg_bin.conf
```

## Why not least squares (or Poisson)?

- **Least squares** (a Gaussian with one constant σ) weights every point equally.
  But a count of 200 is far noisier than a count of 2, so constant-σ scoring
  mis-weights the curve and, worse, reports a badly-calibrated uncertainty — even
  when the point estimate lands near the truth. It also happily predicts negative
  counts.
- **A plain Poisson** ties the variance to equal the mean. Real counts are almost
  always *over*-dispersed (extra biological and technical variation), so a Poisson
  under-states the noise and over-states your confidence. The negative binomial adds
  exactly the dispersion parameter `r` that a Poisson lacks.

## The data

`mrna_decay.exp` is regenerated by the shared `regenerate_data.py`: it simulates the
model mean at the true parameters, then draws one over-dispersed negative-binomial
count per point (seeded, so the committed file is fixed). The expected recovery is
recorded test-side in [`_manifest.py`](../_manifest.py); the fit is exercised by
[`tests/test_tutorial_examples.py`](../../../tests/test_tutorial_examples.py).
