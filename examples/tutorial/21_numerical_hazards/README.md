# Lesson 21 — Numerical hazards (surviving simulations that fail)

**Feature:** the `wall_time_sim` and `max_failed_simulations` guards · **Difficulty:** ★★☆

Every lesson so far assumed every candidate simulates cleanly. Real models are not
so polite: for some parameter values the ODE **diverges**, the solver **stalls**, or
a rate law hits a `sqrt` of a negative number. A fitter that crashes the moment one
simulation fails is useless on such a model. This lesson shows how PyBNF treats a
failed simulation as just a very bad score, and the two config guards that keep a
hazardous fit bounded.

## The hazard: a finite-time blowup

`quadratic_finite_time_growth.bngl` is the scalar ODE

```
dX/dt = k * X^2        X(t) = X0 / (1 - k*X0*t)
```

Its closed-form solution has a **pole** at `t = 1/(k*X0)`: before it, `X` is finite;
at it, `X` shoots to infinity. With the true `k = 0.5` and `X0 = 0.2` the pole sits
at `t = 10`, comfortably past the data window (`t_end = 8`), so the committed
`quadratic_finite_time_growth.exp` is a clean, finite curve rising from 0.2 to 1.0.

But the optimizer explores `k` over `[0.1, 2.0]`, and **any `k > 0.625` drags the
pole inside the window**. Those simulations blow up — the CVODE solver either aborts
with an integration error or grinds to a near-standstill taking ever-smaller steps
toward the singularity.

## Guard 1 — the fit survives (`blowup_survives.conf`)

```
wall_time_sim = 2             # abandon any single simulation after 2 s
max_failed_simulations = 100  # tolerate this many failures before giving up
```

- A failed simulation is **not** a crash. PyBNF scores it as `+inf`, and Differential
  Evolution simply never selects that region again.
- **`wall_time_sim`** caps the wall-clock of each evaluation. Near the pole the
  solver can stall indefinitely; this bounds how long any one candidate may run
  before it is abandoned as a (timed-out) failure. Without it, a single diverging
  parameter set can hang the whole fit.
- **`max_failed_simulations`** is the give-up threshold: the run aborts *only* if
  nothing has succeeded yet **and** this many sims have failed. Because the safe
  region (`k < 0.625`) simulates fine, the run always has successes, so it shrugs off
  the blowups.

```bash
pybnf -c blowup_survives.conf
```

About a quarter of the evaluations fail, the log prints `Job … failed` for each, and
the fit still finishes and recovers `k` to a fraction of a percent.

Note the fit is over **`k` only** — `X0 = 0.2` is the *measured* initial abundance,
a known input, not something to estimate. (Estimating both is poorly conditioned
here: many `(k, X0)` pairs with the same product `k·X0` give nearly the same curve.)

## Guard 2 — a hopeless fit fails loudly (`blowup_aborts.conf`)

What if the hazard is everywhere? `blowup_aborts.conf` puts the search box entirely
inside the blowup region (`k ∈ [3.0, 5.0]`, so the pole is always at `t ≈ 1–1.7`).
Now **every** simulation fails and none ever scores. Instead of proposing
unsimulatable candidates forever, PyBNF gives up once it has seen
`max_failed_simulations` failures with zero successes:

```
Aborted because all jobs are failing
```

This is `max_failed_simulations` doing its other job — telling you something is
structurally wrong (here, the whole search box is unsimulatable) rather than letting
a doomed run spin. In practice you would read that message and fix the model or the
bounds.

## Takeaways

- A simulation that diverges or errors is scored `+inf`; the optimizer routes around
  it. One bad parameter set never crashes the fit.
- Set **`wall_time_sim`** whenever a model *can* stall, so no single evaluation can
  hang the run. (Its default for BNGL models is 3600 s — fine as a backstop, far too
  long as a per-candidate bound on a hazardous model.)
- **`max_failed_simulations`** is the safety valve for a fit where nothing works:
  it aborts with a clear message instead of looping forever.
- Both guards bound *one unit of work*. To bound the **whole fit** — a hazardous model
  can be slow without ever failing — set **`wall_time_fit`** (seconds). When the budget
  runs out PyBNF stops launching work and writes its normal end-of-fit results for the
  best parameter set found so far, plus a `Results/stop_reason.txt` saying why; killing
  the process instead leaves no results at all.

## The data & test

`quadratic_finite_time_growth.exp` is regenerated by the shared `regenerate_data.py`
(the model's own output at the truth, pole safely past `t_end`). The expected
recovery and abort are recorded test-side in [`_manifest.py`](../_manifest.py) and
exercised by [`tests/test_tutorial_examples.py`](../../../tests/test_tutorial_examples.py)
— the survive case additionally asserts that some simulations really did fail (so the
guard demonstration is not vacuous), and the abort case asserts the run raises.
