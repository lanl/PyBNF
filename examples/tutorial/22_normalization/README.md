# Lesson 22 — Normalizing data (fitting shape when the scale is unknown)

**Feature:** the `normalization` key (ADR-0053) · **Difficulty:** ★★☆

A lot of real data has no meaningful absolute scale. A fluorescence trace is in
detector units; a Western blot is in arbitrary intensity; a calcium signal is
reported as **ΔF/F₀** (divided by its own baseline) or as **% of maximum**. The raw
numbers depend on gain and exposure, not just biology — only the **shape** of the
curve carries the kinetics. This lesson fits such data by normalizing the
**simulation** the same way the data was normalized, so the two are comparable.

## The scenario

`conversion.bngl` is a one-step conversion `A → B` (rate `k`). The committed
`conversion.exp` is that reaction recorded in arbitrary units and then normalized —
exactly as an experimentalist would report it:

- **`Obs_A`** (the reactant) divided by its **initial** reading → starts at 1, decays.
- **`Obs_B`** (the product) divided by its **peak** reading → rises from 0 to 1.

Whatever unknown gain multiplied the raw signal has cancelled. Neither the true
`A0 = 100` nor the detector gain appears anywhere in the data.

## Matching the model to normalized data

To score the model against normalized data, PyBNF normalizes the **simulated**
observables the same way before comparing. Because the two columns were normalized
differently, the config declares one rule each:

```
normalization Obs_A = init     # divide simulated Obs_A by its t=0 value
normalization Obs_B = peak     # divide simulated Obs_B by its maximum
```

Now a unitless simulated shape is compared with a unitless data shape, and the only
thing that shapes both — the rate `k` — comes straight back, with no scale parameter
to fit:

```bash
pybnf -c normalized_shape.conf      # recovers k = 0.5
```

The normalization types are:

| type   | operation                                | typical use                    |
|--------|------------------------------------------|--------------------------------|
| `init` | divide each column by its first point    | ΔF/F₀, fold-change from t=0    |
| `peak` | divide each column by its maximum        | % of max, normalized response  |
| `zero` | z-score (subtract mean, divide by sd)    | shape only, mean/scale removed |
| `unit` | rescale to [0, 1]                        | min–max feature scaling        |

The whole-fit form `normalization = <type>` applies one type to every observable;
the per-observable form used here (`normalization <obs> = <type>`, ADR-0053)
overrides it column by column, and `normalization <experiment>.<obs> = <type>`
overrides a single experiment.

## Forgetting to normalize (`no_normalization.conf`)

The cautionary twin fits the **same normalized data with no `normalization` lines**.
The simulation is then scored on its raw scale — `Obs_A` starting near 100, `Obs_B`
climbing toward 100 — against data that lives on [0, 1]. The 100× magnitude gap
dominates the least-squares objective, and since `k` is not a scale it cannot close
it; the fit is dragged far off the truth. Normalized data needs a matching
`normalization` declaration (or an explicit gain nuisance, as in lesson 14).

## Takeaways

- `normalization` normalizes the **simulation** so it can be compared to data that is
  already normalized — it does not rescale your data file for you.
- Pick the type to match how the data was reduced: `init` for baseline-normalized
  traces, `peak` for percent-of-max, `zero` for pure shape.
- Declare it **per observable** when different columns were normalized differently.

## The data & test

`conversion.exp` is regenerated by the shared `regenerate_data.py`, which simulates
the model at the truth and applies the same `init`/`peak` normalization the conf
declares (recorded in [`_manifest.py`](../_manifest.py)). Both confs are exercised by
[`tests/test_tutorial_examples.py`](../../../tests/test_tutorial_examples.py): the
normalized fit must recover `k`, and the un-normalized one must be provably dragged
off it.
