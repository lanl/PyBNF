# Lesson 14 — The measurement layer (fit what the instrument actually reports)

**Feature:** measurement models / `observableFormula` (ADR-0036) · **Difficulty:** ★★☆

The model computes species amounts. An experiment rarely measures those amounts
*directly* — it measures them through an instrument: a fluorescence gain, a ratio,
a log-scale detector. PyBNF bridges the two with a **measurement model**: a formula
evaluated *after* simulation that maps the model's output to what was measured. It
is PEtab's `observableFormula`, written right in the `.conf` and never touching the
model file:

```
observable: obs_scaled, formula: scale * Obs_B
```

This lesson layers three different measurement models on one tiny reaction
(`A --k--> B`, in [`conversion.bngl`](conversion.bngl)) — and recovers the truth
from each.

## The three measurement models

| Conf | Measurement model | What it teaches |
| --- | --- | --- |
| [`conversion_scaling.conf`](conversion_scaling.conf) | `scale * Obs_B` | an **unknown instrument gain** — a nuisance parameter fitted *alongside* the rate |
| [`conversion_ratio.conf`](conversion_ratio.conf) | `Obs_B / (Obs_A + Obs_B)` | a **derived fraction** the simulator never outputs as a column |
| [`conversion_log.conf`](conversion_log.conf) | `log(Obs_A)` | fitting on a **transformed scale** (log space) |

Run any of them from this folder:

```bash
pybnf -c conversion_scaling.conf
```

## The headline: an observation-layer nuisance

The scaling fit is the one to study. `scale` is a free parameter that appears in
**no reaction rule** — it exists only in the measurement formula. This is exactly
PEtab's `observableParameters`: a nuisance declared with the *fit*, not the model.
PyBNF recognizes it as an observation-layer parameter (it is not mistaken for an
orphaned typo), resolves it from the parameter set when it scores each candidate,
and recovers it:

```
#  Simulation   Obj            k                    scale
   gen58ind9    6.3e-12        0.7000001855         1.9999999559
```

Both the reaction rate `k` (true 0.7) and the instrument gain `scale` (true 2.0)
come back exactly, from data that is `scale * B(t)` — you never told the fitter the
gain.

Why is this powerful? Because the alternative — hard-coding a `scale` parameter
into the model and multiplying it into an observable — pollutes the model with
instrument details and forces a separate model per instrument. The measurement
layer keeps the biology (the model) and the observation (the `.conf`) cleanly
separate, so one model serves every experiment that measured it differently.

## Ratios and transforms

- **A ratio** (`conversion_ratio.conf`) is a quantity the model has no single
  species for. `Obs_B / (Obs_A + Obs_B)` is the *fraction* converted — with the
  total conserved it is `1 - exp(-k t)`, dimensionless and self-normalizing (the
  unknown total `A0` cancels). You fit a curve the simulator never emitted.
- **A transform** (`conversion_log.conf`) changes the scale on which residuals are
  taken. `log(Obs_A)` fits the decay in log space, so the small-value tail counts
  as much as the large-value start (relative rather than absolute error). `log` is
  the natural log; for base-10 use `log(Obs_A)/log(10)`.

## What to notice

- **The model file never changed.** All three fits use the *same*
  [`conversion.bngl`](conversion.bngl); only the `observable:` line in the `.conf`
  differs. The observation is configuration, not biology.
- **A formula can name anything in scope** — model observables (`Obs_A`, `Obs_B`),
  fixed model parameters, `time`, and the fit's own free parameters (the
  nuisances). Unknown symbols are rejected at load (see Lesson 13's
  `missing_parameter` fixture for the linter's version of that check).
- **The data is generated by the same layer code that fits it.** The
  [generator](../regenerate_data.py) materializes each `observableFormula` at the
  true parameters to write the `.exp`, so recovery is exact — no hidden transform.
