- **A protocol-block action that names an option the bngsim bridge does not read is classified
  with the model's actions (#1000).** A `simulate` in a protocol block that a `method=>"protocol"`
  scan runs, naming `argfile`, `max_sim_steps`, `output_step_interval` or `print_on_stop`, left
  the model on the bridge, and set-up then refused it saying `auto` picks BNG2.pl for it, which
  it had not. PyBNF cannot run such a model on BNG2.pl either: it simulates the generated `.net`
  file there, which carries no protocol block (#926). So `auto`, and `bionetgen`, now refuse a
  model whose protocol a scan runs whenever they would simulate it with BNG2.pl, saying why, and
  `bngsim` refuses one whose protocol names such an option without claiming BNG2.pl runs it.
  `print_on_stop=>0` without `stop_if` is no longer sent to BNG2.pl or refused under `bngsim`:
  BNG2.pl reads it only beside `stop_if`.
